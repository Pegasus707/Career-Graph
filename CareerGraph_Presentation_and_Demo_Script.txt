[SLIDE 2: PROBLEM STATEMENT - Challenges in Modern IT Learning]
"Every year, thousands of IT and Computer Engineering undergraduates face significant confusion 
when preparing for industry careers. Through our research, we identified four fundamental challenges:

1. Premature High-Level Tool Fatigue:
   Beginners routinely jump straight into complex frameworks like React, Docker, or Kubernetes 
   before mastering essential foundations like the JavaScript event loop, Linux CLI, or HTTP protocols. 
   This causes cognitive overload and leads to course dropout rates exceeding 70%.

2. Static and Non-Adaptive Visualizers:
   Existing platforms like roadmap.sh provide static, read-only SVG diagrams. They cannot evaluate 
   student competencies, adapt to university degree streams, or provide personalized progression.

3. Siloed, Non-Portable Skill Progress:
   When a student completes core subjects like Git, Python, or SQL in a Web Development course, 
   that progress is trapped in an isolated silo. If they pivot to DevOps or AI/ML, they are forced 
   to repeat the same modules from scratch.

4. Unverified 'Honor-System' Checklists:
   Mainstream platforms rely on self-marked checkboxes or passive video view times with zero objective 
   validation, creating a false sense of competency.

Career Graph was engineered specifically to solve these four critical bottlenecks."


[SLIDE 3: PROPOSED SOLUTION - The Career Graph Platform]
"To address this, Career Graph implements a structured 5-Tier Curriculum Hierarchy supported by 
4 Core Technical Pillars.

On the pedagogical side, our hierarchy decomposes education into:
- Tier 1: 6 Industry-aligned Career Tracks,
- Tier 2: Discrete atomic skills structured into dependency graphs,
- Tier 3: Dedicated 1-to-1 course curricula,
- Tier 4: Strict Beginner, Intermediate, and Advanced levels, and
- Tier 5: Granular lessons with actionable theory and runnable code.

Technically, this is powered by our 4 core pillars:
1. A Topological Prerequisite Engine that mathematically locks advanced phases until fundamentals 
   are complete.
2. An Adaptive Onboarding Baseline that calibrates the roadmap to each student's degree and stream.
3. Our Universal Cross-Track Credit System, ensuring skills mastered in one track automatically 
   count in all other tracks.
4. A Server-Graded Proof-of-Skill Engine that evaluates advanced students through tamper-proof 
   micro-quizzes.

I now hand over to Jagruti to present our comparative survey, architecture, and database design."

[SLIDE 5: THREE-TIER DECOUPLED SYSTEM ARCHITECTURE]
[Action: Point to Figure 1 on the slide]
"Slide 5 illustrates our complete cloud system architecture:

- At the Presentation Tier, we have a Vue 3 Single Page Application built using the Composition 
  API and Vite 5.3. Reactive state is managed using Pinia stores, and connector curves between 
  nodes are computed mathematically on an HTML5 SVG canvas.
- At the Application Tier, we run a Node.js 18+ runtime with an Express 4.19 REST API. This tier 
  handles stateless JWT authentication, Bcrypt password hashing, and houses our core skillGapService 
  algorithmic engine.
- At the Persistence Tier, we utilize MongoDB Atlas. We enforce 9 normalized Mongoose 8.5 schemas 
  with compound uniqueness indexes to ensure all progress writes are idempotent.
- In terms of hosting, the frontend is deployed globally on Vercel's Edge CDN with SPA rewrite rules, 
  while the backend is continuously deployed on Render Web Services with git-triggered pipelines."


[SLIDE 6: DATABASE SCHEMA & ENTITY-RELATIONSHIP MODELING]
[Action: Point to Figure 2 on the slide]
"Our database model is structured to maintain referential integrity while supporting high-throughput 
read operations:

- The User and UserProfile collections maintain a strict 1-to-1 association storing authentication 
  hashes, academic stream, degree, and baseline self-ratings.
- The Career collection links to Skill documents, which explicitly store prerequisite and related 
  skill Object IDs.
- Each skill maps 1-to-1 to a Course, which cascades into Level and atomic lesson entities.
- To log student activity safely, CourseProgress and LessonProgress enforce compound unique indexes 
  on user and course or lesson IDs. This guarantees that duplicate network requests or retries will 
  never corrupt user records.
- Finally, SkillQuiz documents store question payloads and server-side answer keys for our validation engine.

I now invite Varsha to explain the algorithmic logic behind prerequisite gating and skill propagation."

[SLIDE 7: CORE LOGIC 1 - Topological Prerequisite Engine]
"Thank you, Jagruti.

The cornerstone of Career Graph's learning methodology is our Topological Prerequisite Engine.
Our roadmap is organized into three strictly governed phases:

- Phase 1: Foundations is unconditionally unlocked upon registration. For example, in the Full Stack 
  track, this covers HTML, CSS, JavaScript, and Git. This ensures that every student solidifies basic 
  syntax and engineering tooling first.
- Phase 2: Core Stack is strictly locked until all Phase 1 skills reach 100% completion. A student 
  cannot access Node.js, Express, or MongoDB until their foundational JavaScript and Git are mastered.
- Phase 3: Advanced & Cloud is locked until Phase 2 is complete, preventing learners from attempting 
  Docker, Kubernetes, or AWS without backend proficiency.

At the micro-level, our algorithm performs topological sort traversals across node dependencies. 
If a student attempts to access a node whose prerequisite Object IDs are incomplete, the engine 
prevents access and dynamically highlights the next recommended skill."


[SLIDE 8: CORE LOGIC 2 - Proof-of-Skill Validation System]
"Slide 8 highlights our Proof-of-Skill Validation System, which enforces objective competency:

1. Advanced Phase Gating:
   Validation quizzes cannot be accessed on day one. A student must reach the Advanced level by 
   finishing lessons or having an evaluated baseline.

2. Anti-Cheating Sanitization:
   When a student opens a quiz, the API explicitly strips out correctIndex and explanation fields 
   before returning the JSON payload. Even if a student inspects DevTools or Network tabs, the 
   answer keys do not exist in the browser.

3. Server-Side Grading:
   The student's submitted option indexes are evaluated exclusively on the backend. Achieving at 
   least 2 out of 3 correct answers (66.7%) awards the Verified Badge (Shield icon), elevates their 
   skill rating to Level 4 (Expert), and atomically marks the course syllabus complete in a single transaction."


[SLIDE 9: UNIVERSAL CROSS-TRACK SKILL PROPAGATION]
"One of our proudest innovations is Universal Cross-Track Skill Propagation.

Consider a real-world scenario:
- A student enrolls in the Full Stack Developer track. They master Git (100%) and Python (100%) and 
  pass the validation quizzes.
- Later in the semester, they decide to explore DevOps or AI/ML.
- In conventional platforms, they would have to re-watch videos and re-complete Git and Python modules.
- In Career Graph, skills are tracked under canonical keys like 'skill-git' and 'skill-python'. When the 
  student switches tracks, the engine immediately checks their universal skill inventory. Git and 
  Python are automatically displayed as 100% Complete and Verified.

This treats learning achievements as portable developer assets rather than course-locked silos.

I now invite Sanyukta to cover our UI engine, advantages, limitations, and future scope."

[SLIDE 11: SYSTEM ADVANTAGES & TECHNICAL LIMITATIONS]
"As engineers, we conducted a rigorous and balanced evaluation of Career Graph.

Our Key Advantages include:
1. Enforced Prerequisite Sequencing: Topological gating prevents premature framework adoption, 
   drastically reducing student dropout rates.
2. Universal Cross-Track Mobility: Mastered skills (Git, Python, SQL) carry over immediately when 
   switching tracks, saving dozens of hours of duplicate study.
3. Tamper-Proof Proof-of-Skill: Server-graded micro-quizzes with client payload sanitization eliminate 
   honor-system cheating and award credible badges.
4. Non-Disruptive Dynamic Navigation: In-canvas preview drawers and 1-click status toggling maintain 
   learner focus without constant page refreshes.
5. Production-Ready Decoupled Stack: Modern Vue 3 SPA + Node/Express REST API delivers sub-100ms 
   UI response times and horizontal cloud scalability.

Equally, we acknowledge our current Technical Limitations:
1. Initial Curriculum Scope: Currently covers 6 high-demand IT tracks; emerging niche fields require 
   ongoing administrator curation.
2. Fixed Validation Quiz Pool: Each skill currently draws from a curated 3-question evaluation pool; 
   future expansion requires randomized question banks.
3. Active Network Dependency: Real-time progress synchronization and server-side quiz grading require 
   active internet connectivity (no local offline PWA caching).
4. Absence of In-Browser Code Sandbox: Assesses conceptual and architectural understanding through 
   quizzes, but does not yet compile live code in a WebAssembly sandbox.
5. Subjective Initial Onboarding: Initial baseline self-ratings rely on student honesty upon sign-up 
   until objectively validated through subsequent micro-quizzes."

PART 3: EXAMINER VIVA & Q&A CHEAT SHEET
========================================================================================

Question 1: Why not simply use roadmap.sh?
Answering Members: Shinde Piyush Anil / Telore Jagruti Kishore
Key Points:
- roadmap.sh is static and read-only.
- It doesn't assess student knowledge or degree stream.
- It lacks prerequisite locking and allows users to blindly jump anywhere.
- It doesn't verify skills or support cross-track progress transfer.

Question 2: How does the Topological Prerequisite Gating work algorithmically?
Answering Members: Tumma Varsha Chandraprakash / Surve Archit Milind
Key Points:
- Implemented in backend skillGapService.js.
- Graph nodes are organized into Directed Acyclic Graphs (DAGs).
- Macro-phases (Foundations -> Core -> Advanced) require 100% of preceding phase skills.
- Micro-nodes verify prerequisite Object IDs prior to unlocking.

Question 3: How do you prevent cheating on the Proof-of-Skill quizzes?
Answering Members: Tumma Varsha Chandraprakash / Surve Archit Milind
Key Points:
- Client GET request projection explicitly removes correctIndex and explanation.
- Answer keys are never transmitted to the browser DOM, local storage, or network response.
- Grading logic executes strictly on the backend API inside quizController.js.

Question 4: How is cross-track progress shared across different careers?
Answering Members: Tumma Varsha Chandraprakash / Surve Archit Milind
Key Points:
- Skills are identified by canonical string IDs ('skill-git', 'skill-python').
- Progress is stored at the user-skill level, not isolated inside career documents.
- When switching tracks, the engine matches canonical skillIds to immediately reflect credit.

Question 5: How do you guarantee data integrity under high traffic or retries?
Answering Members: Telore Jagruti Kishore
Key Points:
- MongoDB compound unique indexes on CourseProgress ({ user: 1, course: 1 }) and 
  LessonProgress ({ user: 1, lesson: 1 }).
- Ensures all write operations are idempotent; network retries cannot create duplicate records.

Question 6: Why did you choose Vue 3 and Node.js/Express over alternatives?
Answering Members: Waychal Sanyukta Amol / Vichare Sanika Sanjay
Key Points:
- Vue 3 Composition API provides fine-grained reactivity for smooth SVG canvas rendering.
- Node.js and Express offer non-blocking I/O, sub-100ms response times, and lightweight REST endpoints.
