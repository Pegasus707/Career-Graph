[SLIDE 1: TITLE SLIDE - Career Graph]
"Good morning respected examiners and teachers.

We are Group Number 06 from the Computer Engineering and IT Department. Our project is 
'Career Graph' — an interactive IT career roadmap platform.

It guides engineering students step-by-step so they know exactly what skills to learn, in what 
order, and tests what they have learned.

Our system is built with Vue 3 on the frontend, Node.js and Express for the backend API, 
and MongoDB Atlas for the database.

Before Sanika and Archit demonstrate the live website, we will quickly explain the problem, 
our solution, and how the system works."


[SLIDE 2: PROBLEM STATEMENT - Challenges in Modern IT Learning]
"Today, engineering students face 4 common problems when preparing for tech jobs:

1. Jumping into advanced tools too early:
   Students try to learn complex frameworks like React or Docker before they even understand 
   basic JavaScript, HTML, or Linux. They get overwhelmed and quit.

2. Static roadmaps:
   Websites like roadmap.sh only show static pictures. They don't test what you know, and they 
   don't track your actual progress.

3. Wasted effort:
   If you learn Git and Python for Web Development, and then switch to DevOps or Data Science, 
   traditional platforms make you start from zero again. Your progress is lost.

4. Fake progress:
   Most websites just let you tick a checkbox with no real test or verification.

We built Career Graph to solve these exact problems."


[SLIDE 3: PROPOSED SOLUTION - The Career Graph Platform]
"Career Graph solves this with two simple concepts:

First, a clear 5-step learning ladder:
From Career Track, down to Skills, Courses, Levels (Beginner to Advanced), and short Lessons.

Second, our 4 core features:
1. Locked prerequisites: You cannot skip the basics.
2. Personalized onboarding: It adapts to your degree and stream.
3. Universal skill credit: Skills you master in one track automatically count in other tracks.
4. Proof-of-Skill quizzes: Short tests that give you a verified badge.

Now, Jagruti will explain our comparison with existing platforms and our system architecture."

[SLIDE 7: CORE LOGIC 1 - Topological Prerequisite Engine]
"Thank you, Jagruti.

Our roadmap follows a strict 3-phase rule so students don't skip the basics:

- Phase 1: Foundations. This is unlocked on day one. For example: HTML, CSS, JavaScript, and Git.
- Phase 2: Core Stack. This is locked until you complete 100% of Phase 1. You cannot jump into 
  Node.js or Express until your basics are mastered.
- Phase 3: Advanced. This unlocks only after Phase 2 is finished, covering Docker, Cloud, and CI/CD.

This simple rule ensures every student builds a solid foundation first."


[SLIDE 8: CORE LOGIC 2 - Proof-of-Skill Validation System]
"To make sure students actually understand the topics, we have a Proof-of-Skill Quiz:

1. It only unlocks once you reach the advanced level of a skill.
2. Anti-cheat protection: The answers are never sent to the browser, so students cannot cheat using 
   browser inspect tools.
3. Passing: If you score at least 2 out of 3 questions, you earn a Verified Badge (Shield icon) 
   and the skill is marked complete."


[SLIDE 9: UNIVERSAL CROSS-TRACK SKILL PROPAGATION]
"Our most practical feature is Universal Skill Sharing.

Imagine this:
A student completes Git and Python in the Full Stack Developer track.
Later, they want to explore DevOps or AI.
In other platforms, they would have to do Git and Python all over again.
In Career Graph, the system recognizes that they already verified Git and Python, and marks them 
complete instantly in the new track!

This saves students dozens of hours.
Now Sanyukta will cover our UI, advantages, and deployment."

PART 3: COMMON EXAMINER QUESTIONS & SIMPLE ANSWERS
========================================================================================

Q1: Why not just use roadmap.sh?
Answer (Piyush / Jagruti):
"roadmap.sh is just a static picture. It doesn't track progress, doesn't lock prerequisites, 
and doesn't test student skills."

Q2: How does prerequisite locking work?
Answer (Varsha / Archit):
"Our backend checks if all skills in Phase 1 are 100% complete. If even one basic skill is missing, 
Phase 2 stays locked."

Q3: How do you prevent cheating on quizzes?
Answer (Varsha / Archit):
"The correct answers are never sent to the browser. The user's answers are sent to the server, 
and the server grades them."

Q4: How does skill sharing work when switching careers?
Answer (Varsha / Archit):
"Skills use universal IDs like 'skill-git'. So when you switch tracks, the system checks if you already 
have that skill ID verified."

Q5: Why did you choose Vue 3 and Node.js?
Answer (Sanyukta / Sanika):
"Vue 3 makes the interactive canvas fast and smooth, and Node.js with Express gives fast REST API 
responses under 100 milliseconds."
